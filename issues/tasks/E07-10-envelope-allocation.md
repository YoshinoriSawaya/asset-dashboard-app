# E07-10: 単一口座内での仮想配分管理(封筒予算方式)
親: [E07: 目標(Goal)管理機能](../epics/E07-goal-management.md)

## 概要
車貯金・生活防衛資金などが実際には同一の銀行口座で管理されている
前提で、口座残高をGoalごとに仮想的に配分(封筒予算方式)できる
ようにする。実口座を分けなくても、アプリ上でGoalごとの進捗を
追えるようにする。

## E07-02からの変更点
E07-02は「Goal 1つ:口座1つ」の単純な紐づけを想定していたが、
実際には複数のGoalが同じ口座に同居するため、口座単位ではなく
「口座内の配分額」単位でGoalと紐づける方式に変更する。
[E07-02](E07-02-account-balance-linking.md) はこのタスクに統合した
(E07-02のステータスは「E07-10に統合」)。

## 設計
- 各口座に対して、Goalごとの配分額(または配分比率)を設定できる
- 「配分済み合計」が口座の実残高を超えないよう整合性チェックを行う
- 配分先のないGoalに含まれない差額は「自由に使えるお金」として
  自動的に表示する

## 完了条件
1つの口座残高から、車貯金・生活防衛資金などの複数Goalへの配分額を
設定でき、口座残高が更新されるとそれぞれの進捗が連動して更新される。

## 作ったもの
「口座」は資産推移CSVの系列(例: 預金・現金)として扱い、**同じ系列を測る目標が2つ以上あれば、
系列の値を一覧で上の目標から順に、それぞれの目標額まで割り当てる**。余りが「自由に使えるお金」。
計算は `data/Allocation.kt`。一覧を読むとき(`ItemOverview.load`)に反映するので、
進捗・通知・予測・AI用の書き出しなど、目標の「現在」を見るところは全部割当額を見る。

| 系列 | 目標(上から) | 割当 |
|------|-------------|------|
| 預金・現金 2,000,000 | 生活防衛資金(目標 1,800,000) | 1,800,000(満) |
| | 車(目標 1,000,000) | 200,000 |
| | 自由に使えるお金 | 0 |

- 目標の詳細に「◯◯を◯つの目標で分けています」「上から◯番目。この目標に ◯円」
  「上の目標に回した分 / 自由に使えるお金」と、順番を変える「上へ」「下へ」
- 順番は一覧の並び順(`sortOrder`)そのもの。動かすと一覧に出ている目標全部に
  -N〜-1 を振り直して Drive の settings にまとめて保存する(`GoalOrder`)
- DBの変更は無い

## 設計の決定

### 配分額を入れるのではなく、上から満たす(本人が選んだ)
3つの案を出して本人が選んだ(2026-09-26)。

| 案 | 捨てた理由 / 選んだ理由 |
|----|------------------------|
| **上から順に満たす** | 入れるものが無く、残高が変われば進捗が勝手に追従する(完了条件の「連動して更新」がそのまま満たせる)。「整合性チェック」も要らない(割り当ては残高を超えようがない) |
| 配分額を入れる | 残高が動いても配分は入れ直すまで変わらない。残高を超えたときの扱いが要る |
| 割合で分ける | 目標額と関係なく分かれるので、満ちた目標にも入り続ける |

### 系列を「口座」とみなす
明細(E01)がどの口座のものかは今は見分けていない(口座の見分け方は未決)。一方、資産推移CSVの
系列は口座の種類ごとの残高そのものなので、これを分ける単位にした。口座ごとの残高が
系列として取れるようになれば、そのまま使える。

### 目標が1つだけの系列は分けない
分けると割当は目標額で止まり、進捗が100%で頭打ちになる。生活防衛資金の「何か月分あるか」
(E09-02)も目標額で止まる。分け合う相手がいないなら、これまでどおり系列の値をそのまま使う。

### 毎年の枠と、目標額が分からない目標は分けない
毎年の枠(E07-09)の系列は使った額の累計で、残高ではない。生活費から出す目標で明細がまだ
無ければ目標額が分からないので0を割り当て、下の目標の分を食わないようにした。

### 割当額で頭打ちになると困るところは「使える額」を見る
- **いつ目標を割るか(E09-02)**: 満ちている生活防衛資金の割当額は目標額ちょうどなので、
  そのまま数えると「今月中に割る」になってしまう。系列 − 上の目標の分(`availableYen`)で数える
- **いつ届くか(E09-01)**: 系列が「上の目標の分 + 自分の目標額」に届いたときが達成、として
  系列の推移から予測する(上から満たすので、これで正確)

### 色は並び順で決める
E07-13の積み上げグラフで使う目標の色は、一覧に出ている目標の中で上から何番目か。
順番を変えると色も変わるが、同じ画面の中・グラフと詳細の間では常に同じ色になる。

## 検証 (2026-09-26)
**JVMユニットテスト(242件、うち追加10件)**: `AllocationTest`(満たし方・マイナス残高・
目標額不明・2つ以上のときだけ・毎年の枠は除く・使える額で割るまでの月数・積み上げ・
上の分を足した達成予測)、`GoalOrderTest`(動かして振り直す・端)、`AiExportTest`(割当と何番目か)

**エミュレータで、実データのキャッシュに一時的な目標を2つ足して確認した**
(預金・現金の50%と30%を目標額にした2つ。最後に消した。Driveには書いていない):
- 一覧で2つとも100%(上から満ちて、20%が余る)
- 下の目標の詳細に「預金・現金を2つの目標で分けています」「上から2番目」、
  「上へ」は押せて「下へ」は押せない(2番目のうち2番目)

## 未検証・積み残し
- **「上へ」「下へ」で Drive の settings に保存する流れはエミュレータで押していない**
  (確認用の目標が Drive に書かれてしまうため)。並びの計算はユニットテストで確認
- 口座ごとの残高の系列が取れるようになったときの見直し(明細の口座の見分け方は未決)
- 新しく作った目標は並び順 -1 なので、一度も動かしていなければ一番下の目標と名前順で並ぶ
