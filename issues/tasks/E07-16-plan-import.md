# E07-16: 大型出費の予定のまとめ取り込み
親: [E07: 目標(Goal)管理機能](../epics/E07-goal-management.md)

## 概要
本人が表計算で作っていた長期の出費計画を、E07-15のリマインダー(見込み額・何年ごと・積立先)として
まとめて登録できるようにする。1件ずつ画面で入れるのは、項目が多く(十数件)手間が大きいため。

## 完了条件
1行1項目のCSVをDriveに置くと、アプリで中身を確かめてからリマインダーとして登録できる。

## 作ったもの
- `ui/PlanImport.kt`(純粋関数): Driveの `settings/plan.csv` を読み、今の項目と突き合わせて登録の中身を作る
  ```
  名前,次の時期,何年ごと,見込み額,積立先
  車検,2027-03,2,150000,車・家電
  ```
  - 次の時期: `2027-03`(その月の1日)・`2027-03-15`・`2027/3/15`
  - 何年ごと: 空か1なら毎年、0なら一度だけ
  - 積立先: 積立の目標の名前。空なら積立に入れない。無ければ作る(5年でならす・物価上昇0%・系列なし)
  - 文字コードはUTF-8/Shift_JISのどちらでも(CSV取り込みと同じ判定)
- `ui/PlanImportScreen.kt`: トップの「大型出費の予定をまとめて取り込む」から開く。
  「新しく N件 / 置き換え N件 / 読めない行 N件」と、新しく作る積立の目標、1件ずつの中身を見せ、
  「登録する」で settings/items.json に足す

## 設計の決定

### 一度だけ取り込み、以後はアプリで編集する(本人が選んだ)
捨てた案:
- **Driveの予定ファイルを正にして同期のたびに読む**: シートで管理し続けられるが、アプリで「済みにする」
  (次の期日へ進める)や編集をすると、次の同期でファイルの内容に戻る。済みの扱いを別に持つ設計が要る
- **エミュレータ経由で私が登録する**(デバッグ版だけの取り込み): 手間は最小だが機能として残らない

取り込み口はアプリに残るので、年に一度シートを見直したときにも使える。

### 名前で突き合わせる
同じ名前のリマインダーがあれば置き換える(idと並び順は残す)。取り込み直しても増えない。
CSVの中に同じ名前が2行あれば、2行目以降は読めない行にする(どちらが正しいか分からない)。
アプリで消した予定は、同じCSVを取り込み直すとまた入る。

### ファイルは settings に置く(inboxではない)
inboxはCSVの取り込み口で、置いたものは全部、銀行明細などとして読もうとする。予定は人が決めた設定なので
settingsに置く。取り込んだあともファイルは消さない(次の見直しの元になる)。

### 登録の前に中身を見せる
settingsは人が入れたもので、作り直せない(docs/architecture.md)。まとめて書き換えるので、
何が増えて何が置き換わるかを先に見せてから書く。

### 表の値の作り方(本人の表から作ったとき)
表は年単位で、項目ごとに周期と額があり、物価上昇を後から掛けている(各年の合計 = 今の値段の合計 × 1.02^年数
で、全行で一致した)。今の値段の額と、最初の年・周期を列ごとに読んでCSVにした。表とCSVの突き合わせは
スクリプトで行い、額は会話に出していない。CSVはリポジトリの外に置いた。

- 月は表に無いので仮に決めた(税は納期の月、それ以外は年の1月)。毎年のものは、今年分は払い済みとして翌年から
- **額が途中で変わる項目**はリマインダー1つでは表せない。固定資産税は段階的に上がる、パソコンは1回目だけ安い、
  テレビは今年の予定だけ高い。今は次の回の額で入れ、変わる前に本人がアプリで直す

## 検証 (2026-09-26)
**JVMユニットテスト(293件、うち追加4件)**: `PlanImportTest`(見出しと書き方の揺れ、読めない行の理由と
行番号、同じ名前が2行、Shift_JIS、名前での置き換えと積立の目標を作る、取り込み直しても増えない)

**エミュレータで、本人がDriveに置いた実物の plan.csv で確認した**(額は出していない):
- 「新しく 17件 / 置き換え 0件 / 読めない行 0件」、新しく作る積立の目標は2つ
- 17件すべて、次の時期・何年ごと・積立先がCSVのとおり
- 本人の指示で「登録する」を押した。「登録しました(新しく 17件、置き換え 0件)」と出て、Driveから作り直した
  キャッシュに、積立の目標2つ(5年・0%・系列なし)とリマインダー17件(全件に積立先、何年ごと2以上が11件)が入った。
  本人のDriveの settings/items.json に書いたのは、このときが初めて

**スマホ(2.1.0)で確認した** (2026-09-26):
- 2.1.0を入れて同期すると、同じときにinboxに置かれていた19ファイルの取り込みは通ったが、キャッシュの作り直しが
  「backupを落とせない」で止まった(今のキャッシュを残す分岐。E02-03で未検証だった道を、実機で初めて通った)。
  エミュレータのデバッグ版で同じ同期をすると、同じbackup 22件を全部読めて作り直せたので、一時的な通信の失敗と判断した
- もう一度同期すると作り直せ、積立の目標2つとリマインダーが一覧に出た。通知も許可された

## 未検証のまま残したこと
- 額が途中で変わる項目(上記)は、本人がアプリで直す必要がある
- スマホ(2.0.0)はまだ新しい列(何年ごと・積立先・積立の設定)を知らない。2.1.0を入れるまで、スマホでは
  毎年のリマインダーとして見え、積立の目標は読めずに一覧に出ない
- **古い版で settings を保存すると、新しい項目が消える。** `Settings.save` は読めた項目だけを丸ごと書き戻すので、
  2.0.0 で目標・リマインダー・系列を1つでも保存すると、積立の目標と何年ごと・積立先がDriveから落ちる。
  同期(読むだけ)なら消えない。2.1.0を入れるまでスマホで保存しないよう本人に伝えた。
  読めない項目や知らないキーをそのまま残して書き戻す作りにはなっていない(古い版と新しい版を同時に使う想定が
  無かった)。新しい版を入れる前に新しい項目を登録すると、また起きうる
- 取り込んだ積立の目標のならす年数・物価上昇率・測る系列は、本人が目標の編集で決める
