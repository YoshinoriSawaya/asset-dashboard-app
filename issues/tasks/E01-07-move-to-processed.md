# E01-07: inbox→processed移動処理
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
取り込みに成功したCSVをinboxからprocessedへ移動する。

## 完了条件
取り込み済みファイルがprocessedに移動し、inboxが空になる。

## 設計の決定

### 記録してから移動する(順序が重要)
逆にすると壊れ方が見えなくなる。

| 順序 | 移動後に失敗したら |
|------|--------------------|
| 移動 → 記録 | processedにあるが記録が無い。次回inboxに無いので**二度と見つからず黙って消える** |
| **記録 → 移動** | inboxに残ったまま記録済み。「取り込み済みが残留」として見え、次回リトライできる |

後者を採った。壊れるなら見える側に倒す。

### Driveに「移動」APIは無い
親フォルダの追加と削除(`addParents` / `removeParents`)で表現する。
中身はコピーされないので**ファイルIDは変わらない**。
つまり移動してもE01-03の取り込み済み判定は効き続ける。

### 移動の失敗は取り込みの失敗ではない
移動できなくても、読んで記録したことは成立している。
`MOVE_FAILED` として区別し、次回の同期で移動だけリトライする
(`MOVE_RECOVERED`)。

### 読めなかったファイルはinboxに残す
記録もしないし移動もしない。直して置き直せば次回そのまま拾われる。

## 実装
`drive/InboxSync.kt` が1周ぶんの処理をまとめる。

1. `InboxScanner`でinboxを見る
2. 前回移動に失敗して残っているもの(`alreadyIngested`)の移動をリトライ
3. 未取り込み(`pending`)を読む → 記録 → 移動

結果は`Report`として返す。状態は4つ:

| 状態 | 意味 |
|------|------|
| `INGESTED` | 取り込み・移動とも成功 |
| `MOVE_RECOVERED` | 前回の移動失敗から回復 |
| `MOVE_FAILED` | 取り込みはできたが移動できない |
| `FAILED` | 読めなかった。inboxに残る |

## 検証結果 (2026-09-25)
エミュレータで実データ3件。

1回目:
```
取り込み3件
・資産推移月次 (10).csv  取り込み: 資産推移形式
・meisai.csv             取り込み: 年月日・お引出し・お預入れ形式
・20260925005806.csv     取り込み: 取引名・取扱日付・金額形式 / 読めない行 1
```

2回目:
```
inbox=0件 未取り込み=0件 残留=0件
新しいファイルは無し
```

DBの`ingested_file`に3件記録されていることも確認済み。
Drive上でも3ファイルがprocessedに移っている。

`MOVE_RECOVERED`の経路は**未検証**。移動が失敗する状況を作れていない。

## 未決の論点: inboxに戻したファイルをどう扱うか

いまは「記録済みで、かつmodifiedTimeが同じ」ファイルをinboxで見つけたら、
**読み直さずにprocessedへ移動するだけ**。前回の移動失敗からの回復を
意図した挙動。

ところが、人間がprocessedからinboxへファイルを戻す動機はたいてい
「もう一度取り込ませたい」なので、期待とずれる。
CLAUDE.mdの「inboxに放り込むだけで、あとはアプリ側が処理する」という
原則からすると、**inboxにあるものは読み直す**ほうが素直。

読み直す側に倒すなら、同じデータを二重に取り込まない仕組み
(E01-11の重複検出)が先に要る。**E01-11の後に再検討する。**

## E02に持ち越す注意
現時点ではパース結果をDBに保存していない(保存先のスキーマがE02のため)。
つまり**いま取り込んだ3ファイルは、読まれて記録されただけで中身は
どこにも残っていない**。

E02でDB保存を実装したら、processedにあるファイルを読み直す必要がある。
手っ取り早いのは以下のどちらか:

- Driveでprocessedからinboxへファイルを戻す
- `ingested_file` テーブルを空にする(エミュレータなら
  `adb shell sqlite3 .../asset-dashboard.db "DELETE FROM ingested_file;"`)
