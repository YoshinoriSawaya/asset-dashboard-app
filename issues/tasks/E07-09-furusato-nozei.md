# E07-09: ふるさと納税枠の管理
親: [E07: 目標(Goal)管理機能](../epics/E07-goal-management.md)

## 概要
年収から算出される控除上限額をGoalとして登録し、その年にどこまで
寄付を使ったかを追跡する。年末が近づいても枠が残っていれば通知する。

## 完了条件
寄付するたびに使用済み額が更新され、上限額に対する進捗が見える。
年末が近づいても未使用枠があれば通知が届く。

## 作ったもの
ふるさと納税専用ではなく、**「毎年1月にリセットする枠」**という目標の種類を足した
(`Item.Goal.resetsYearly`)。NISAの年間投資枠などにも使える。

| 操作 | 場所 |
|------|------|
| 枠を作る | 目標の追加で「毎年1月にリセットする枠」をオンにし、上限額を入れる |
| 寄付したら記録する | 目標の詳細の「使った分を足す」に今回の額を入れる |

- 進捗は**今年使った額 ÷ 枠**。詳細には「今年使った額 / 枠 / 残りの枠(◯年末まで)」
- 系列を選ばなければ、目標の名前の系列に記録する(最初の記録で手入力の系列ができる)
- 記録はDriveの `corrections` に手入力の点として残る(E03-04と同じ道)

DBは v3 → v4(列を1つ足しただけなのでAutoMigration)。

## 設計の決定

### 上限額は計算せず、本人が入れる
概要には「年収から算出」とあるが、実際の控除上限は家族構成・他の控除
(住宅ローン控除など)・住民税の所得割額で変わり、制度の改正でも変わる。
アプリの中で計算すると間違いやすく、間違いに気づきにくい。ふるさと納税の
サイトのシミュレーターで出した額を入れてもらう。

### 「毎年リセットする枠」として汎用にする
ふるさと納税専用のテーブルや画面を作らない(CLAUDE.mdの「汎用スキーマで
拡張する」)。NISAの年間投資枠(E07-08・E10-04で使う)も同じ形で扱える。

### 系列の値は「今年の累計」、記録は「今回の額」
系列の点は時点の値(E02-01)なので、寄付1回ごとの額ではなく今年の累計を持つ。
人が累計を計算しなくて済むよう、「使った分を足す」は今回の額だけを受け取り、
今年の最新の累計に足して今日の点にする。同じ日に2回足しても、その日の点が
累計で上書きされる(補正のキーが「項目 + 日付」のため)。

### 去年の点は数えない
今年の点が無ければ「今年使った額 0円」(不明ではない)。年が明けて最初の
記録は0から足す。

### 不足分の提案(E07-07)は出さない
枠の「残り」は埋めるものではないので、「不足分を埋めるには」は出さない。
残りは「残りの枠」と言う。

## 検証 (2026-09-26)
**JVMユニットテスト(176件、うち追加6件)**: `YearlyAllowanceTest`
(今年の累計だけを数える、今年まだ無ければ0、足す計算と年明け、settingsとの往復、
系列の既定、AI用の書き出しで枠として出す)

**エミュレータでのインストルメントテスト(9件、うち追加1件)**: v3 → v4

**エミュレータで、Driveに実際に書いて確認した**(確認用の目標、最後に全部消した):

| 手順 | 結果 |
|------|------|
| 「毎年1月にリセットする枠」、枠100,000円で作る | 系列は目標の名前になり、「今年使った額 0円 / 残りの枠 100,000円(2026年末まで)」 |
| 10,000円を足す | 今年使った額 10,000円、手入力の点ができた |
| 同じ日に5,000円を足す | 今年使った額 15,000円(同じ日の点が累計で上書き) |
| 目標を消し、記録を取り消す | 148点・4項目・補正0件に戻った |

確認の途中、adbで「毎年1月にリセットする枠」のスイッチを押したつもりが
外れていた。スイッチは説明文と並べた行の縦中央にあり、見出しの文字の高さとは
ずれる(development.mdの落とし穴に書いた)。
