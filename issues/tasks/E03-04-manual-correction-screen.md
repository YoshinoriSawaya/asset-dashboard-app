# E03-04: 手動補正入力画面(E01-10と連動)
親: [E03: ダッシュボードUI・詳細画面](../epics/E03-dashboard-ui.md)

## 概要
自動パースが失敗した項目や、CSVに載らない現金などの数値を
手動で入力・修正できる画面を作る。入力内容はE01-10でDriveの
correctionsに書き戻す。

## 完了条件
アプリ内で数値を編集すると、ローカルDBとDrive(corrections)の
両方に反映される。

## 作ったもの

| 入口 | 用途 |
|------|------|
| Metric詳細の「値を補正・手入力」 | その系列の値を直す・足す。日付と金額は最新の点で埋めておく |
| トップの「+ 手入力の系列を追加(現金など)」 | CSVに載らない系列を、名前から入れる |
| Metric詳細の補正一覧の「取り消す」 | 補正を消す。CSVの点があればその値に戻る |

| ファイル | 中身 |
|---------|------|
| `ui/CorrectionScreen.kt` | 系列・日付・金額・メモの入力と保存 |
| `ui/CorrectionForm.kt` | 入力の検証と、補正の種類の決め方(純粋関数) |
| `DashboardViewModel.saveCorrection / deleteCorrection` | Driveへの書き戻しとキャッシュの作り直し |
| `Corrections.upsert / remove` | 補正の一覧に足す・消す |

## 設計の決定

### Driveに書けなければ、ローカルも変えない
保存は「Driveのcorrectionsを読む → 足す → 丸ごと書き戻す → キャッシュを
作り直す」の順。**オフラインやDriveに書けないときは何も変えずに理由を出す。**

ローカルだけ直すと、次の同期でキャッシュをDriveから作り直したときに
**補正が黙って消える**(E02-03)。見た目上は保存できたのに後で消えるより、
その場で「保存しない」と言うほうがよい(CLAUDE.mdの「壊れるなら見える側に」)。

correctionsを**読めない**ときも保存しない。読めないまま書くと、既存の補正を
全部消してしまう(`Corrections.load` がnullを返すようにしたのはE02-03)。

### 保存後はキャッシュを作り直す
ローカルのDBに点を1つ書き足すだけのほうが速いが、取り消しのときは
「CSVの値に戻す」必要があり、元の値はbackupにしか無い。保存も取り消しも
同じくDriveから作り直す道を通す。今は数秒〜10秒ほどかかる。

### 補正の種類は入力から決める
その日にCSVの点があれば `OVERRIDE`(直す)、無ければ `MANUAL`(足す)。
人に選ばせない。区別は由来を残すためだけのもの(E01-10)。

### 同じ日の補正は上書きする
`Corrections.upsert` は同じ「項目 + 日付」の古い補正を置き換える。
後勝ちなので残しても結果は同じだが、取り消せない古い補正でファイルが
膨らむのを避ける。

### 金額の入力はCSVの読み方より厳しくする
CSV用の `FieldParsers.parseAmount` は既知の列向けにわざと緩い(`ABC123` でも
123を返す)。手入力では `1O00`(オー)のような打ち間違いを通したくないので、
カンマ・円・¥・マイナスを落とした残りが数字だけのときに限る。

### 補正の入口は詳細画面の上に置く
最初は月次の表の下に置いたが、エミュレータで確かめたとき**スクロールしないと
ボタンが見つからなかった**。最新値のすぐ下に移した。

### 保存は画面を離れても止めない
保存・取り消しはViewModelのスコープで走らせる。画面を戻ってもDriveへの
書き込みが途中で止まらない。完了の通知が届いたとき、その画面がもう一番上に
なければ閉じない(別の画面を閉じてしまわないように)。

## 検証 (2026-09-25)

**JVMユニットテスト(134件、うち追加5件)**: `CorrectionFormTest`
- 金額の書式(カンマ・円・¥・マイナス)、打ち間違いを通さない
- 日付の検証(2月30日などを弾く)
- 補正の種類の決め方、同じ日の上書き・取り消し

**エミュレータで実データ、Driveに実際に書いて確認した**。
確認のための値だけを使い、最後に全部取り消した。

1. トップから手入力で系列 `test-manual` を足した → DBに `MANUAL` の点と
   自動生成の項目ができ、一覧に出た
2. **ローカルの点と項目を全部消して同期** → `test-manual` の点が戻った
   (Driveのcorrectionsに入っていることの確認。入れ直しと同じ状況)
3. 年金の最新の点を1円に補正 → `OVERRIDE` になり、詳細の補正一覧に
   「CSVの値を補正」と出た → 「取り消す」で**元のCSVの値に完全に戻った**
   (元の値と比較して一致)
4. `test-manual` を取り消した → 点も項目も消え、148点・4項目・補正0件に戻った

Driveの `corrections/corrections.json` は、この確認で作られ、今は空の一覧になっている。

## 未検証・未実装のまま残したこと
- **オフラインで保存したときの表示**は実機で見ていない(分岐はコードのみ)
- 手入力の系列の点を全部取り消すと、系列ごと消えるので、詳細画面が
  「この項目は見つかりません」になる。自動でトップに戻すほうが親切
- 日付はテキストで入れる。カレンダーから選ぶUIは無い
- 補正のメモは保存するが、画面には出していない
- 保存のたびにキャッシュを作り直すので、backupが増えると遅くなる(E02-03の積み残しと同じ)
