# E01-08: エラー時のlogs書き込み処理
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
パースまたはバリデーションに失敗したファイルについて、失敗理由を
logsフォルダにテキストとして記録する。

## 完了条件
失敗したファイルについて、いつ・どのファイルが・なぜ失敗したかが
logsから確認できる。

## 設計の決定

### 生のCSV行は書かない
読めなかった行には口座番号や氏名が入る(E01-04で実データで確認した)。
logsはDrive上にあり、logcatより人目に触れやすい。

**行番号と理由だけ書く。** 元ファイルはprocessedフォルダにあるので、
行番号で突き合わせれば中身は本人が見られる。
ログに中身を複製する必要は無い。

ログの末尾にもその旨を書いてあるので、後から見て「なぜ中身が無いのか」
で悩まずに済む。

### 1回の同期につき1ファイル(追記しない)
追記方式だと「落として、足して、上げ直す」が必要で、途中で失敗すると
**過去のログごと壊す**。毎回新しいファイルを作れば既存のログは絶対に
壊れない。ファイル名は `yyyyMMdd-HHmmss.log`。

### 問題が無い同期ではファイルを作らない
logsに何かあること自体が「見るべきものがある」という合図になる。
毎回ログを作ると、その合図が消える。

### ログが書けなくても同期は失敗にしない
ログ書き込みで例外を投げると、取り込みは成功しているのに全体が
失敗扱いになる。本末転倒なので握って`Log.w`に落とすだけにする。

## ログに載る条件
- ファイル自体が失敗した(`FAILED`)
- 取り込めたが移動できなかった(`MOVE_FAILED`)
- 取り込めたが読めない行があった(件数と行番号)

成功しただけのファイルは並べない。

## 出力例
```
同期日時: 2026-09-25 10:30:00
結果: 取り込み1件 / 失敗1件

── meisai.xlsx
   失敗: Excel(xlsx)かzipのように見える。CSVで書き出して置き直す

── 20260925005806.csv
   取り込み: 取引名・取扱日付・金額形式 / 読めない行 1
   読めなかった行 1件:
     7行目: 金額が空

※ 読めなかった行の中身はここには書かない(口座番号などが入るため)。
   元のファイルはprocessedフォルダにあるので、行番号で突き合わせる。
```

## 実装
- `drive/DriveApi.uploadTextFile()` ... multipartで新規作成。
  Driveのアップロードはエンドポイントが別ホスト(`/upload/drive/v3`)。
- `drive/SyncLog.kt` ... 中身の組み立て(`render`)と書き込み(`writeIfNeeded`)。
  `render`を分けてあるのでテストから中身を直接確かめられる。

## 検証結果 (2026-09-25)
ユニットテスト7件PASS。特に「生データがログに出ないこと」は
口座番号と氏名を含む行を食わせて、出力に含まれないことを確認している。

**Driveへの実書き込みは確認済み。** 読めない行を1つ含むCSVを再取り込み
したところ、`logsに 20260924-165649.log を書いた` が記録された。

ただし**ファイル自体が失敗するケース**(xlsxを置いた等)は未検証。
壊れたCSVが手元に無いため。ログの中身の組み立ては上のユニットテストで
確認している。
