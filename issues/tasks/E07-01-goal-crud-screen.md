# E07-01: Goal項目のCRUD画面
親: [E07: 目標(Goal)管理機能](../epics/E07-goal-management.md)

## 概要
Goal項目(車購入、PC買い替え等)を自分で追加・編集・削除できる
画面を作る。目標金額もここで入力する(旧E07-04から移した範囲)。

## 完了条件
アプリ内から新しいGoalを追加でき、一覧・詳細に反映される。

## 作ったもの
| 入口 | 画面 |
|------|------|
| トップの「+ 目標を追加」 | `GoalEditScreen`(新規) |
| 目標の詳細の「編集・削除」 | `GoalEditScreen`(編集) |

入れるもの: 名前、目標額、進捗を測る系列(手元の系列から選ぶ。なしも可)、
期日(任意)。削除は2回押させる。

保存先はDriveの `settings/items.json`(E02-01)。組み立ては `GoalForm`(純粋関数)。

## 設計の決定

### 補正(E03-04)と同じ流れで書く
「Driveから読む → 足す・置き換える・消す → 丸ごと書き戻す → キャッシュを作り直す」。
**Driveに書けなければローカルも変えない**、**読めなければ書かない**
(既存の項目を消してしまうため)も同じ。ViewModelの `editOnDrive` に
まとめ、補正と目標の両方がそれを通る。

### 進捗を測る系列は選ばせる
名前から自動で推測しない(`車貯金` → `預金・現金` のような対応付けはしない。
CLAUDE.mdの「対応付けはしない」)。手元の系列をチップで並べて選ぶ。
「なし」も選べる(その間は進捗不明)。

### 目標は一覧の上に出す
新しい目標の並び順を -1 にして、Metric項目(0)より前に出す。

### 削除は2回押させる
Driveから消すので、1回目は「もう一度押すと削除します」に留める。
削除したら詳細画面も意味が無いので、トップまで戻る。

## 検証 (2026-09-25)
**JVMユニットテスト(150件、うち追加4件)**: `GoalFormTest`
- 新規のidと並び順、編集でid・並び順・非表示を引き継ぐ
- 入力の誤り(名前なし、0以下、打ち間違い、日付の形)を通さない
- settingsの項目の置き換え・削除

**エミュレータで、Driveに実際に書いて確認した**。確認用の目標 `test-goal` を使い、最後に消した。

| 手順 | 結果 |
|------|------|
| トップから追加(目標額・期日・系列 `預金・現金`) | 一覧の一番上に出た |
| ローカルの項目を全部消して同期 | Driveから戻った |
| 詳細 → 編集で目標額を変える | 変わり、詳細画面に戻った |
| 削除(2回押す) | 消えてトップに戻った。148点・4項目に戻った |

Driveの `settings/items.json` はこの確認で作られ、今は空の一覧になっている。

途中で、編集の保存が効かないように見えた。**確認の操作でキーボードが保存
ボタンを覆っていて、タップがキーボードに当たっていた**のが原因で、アプリの
不具合ではなかった(development.mdの落とし穴に書いた)。
