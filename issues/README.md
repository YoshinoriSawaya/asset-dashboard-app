# 資産ダッシュボードアプリ - Issue一覧

エピック(親イシュー)は `epics/`、タスク(子イシュー)は `tasks/` に
フラットに置く。ファイル名のプレフィックス(E00, E01...)でエピックに
紐づく。

各タスクファイルには**設計判断の理由と検証結果**を残す。
「実装した」だけでは後から役に立たないので、他の選択肢を捨てた理由と、
未検証のまま残したことも書く。

## 運用ルール
- 各タスクのステータスは「未着手/進行中/完了」の3段階。
  他のタスクに吸収したものは「<吸収先>に統合」とし、ファイルは残す
  (例: [E07-02](tasks/E07-02-account-balance-linking.md))
- タスクを完了したら、対応する親エピックのチェックボックスも更新する
- 完了の体裁を整えるために、未検証・未実装を黙って落とさない。
  タスクファイルに明記する
- 新しいアイデアはこのissues構造に落とし込む前に、まずローカルの
  メモとして書き留めておき、形になったらタスク化する
