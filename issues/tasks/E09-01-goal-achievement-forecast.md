# E09-01: Goal達成予測日の計算
親: [E09: 将来予測機能](../epics/E09-forecasting.md)

## 概要
各Goal(車購入X万、PC買い替え等)について、直近数ヶ月の平均
積立ペースから「このペースならいつ目標額に到達するか」を計算し、
詳細画面に表示する。

## 完了条件
Goal詳細画面に「現在のペースなら◯年◯月頃に達成見込み」という
予測日が表示される。

## 作ったもの
`GoalForecast`(純粋関数)。目標の詳細画面に「今のペースなら」を出す:

| 状態 | 表示 |
|------|------|
| 届く | `2027年7月ごろ達成(月あたり +◯円)`。期日があれば「間に合う/間に合わない見込み」 |
| 横ばい・減っている | `届かない(この半年は月あたり -◯円)` |
| 期間が短い | `データが短く、まだペースを出せない` |
| 届いている | `達成済み` |

期日に間に合わない(または届かない)ときは、`期日に間に合わせるには 月々 ◯円` も出す。
最後に「積立だけでなく値動きも入った目安です」と添える。

## 設計の決定

### ペースは「約半年前の点から最新の点まで」
概要の「直近数ヶ月の平均積立ペース」。資産推移の点は等間隔ではなく、直近1か月に
点が詰まっている。月ごとの増減の平均を取ると、点の多い月に引っ張られる。
約半年(182日)前の点と最新の点の差を、その間の**日数**で割って1日あたりの
増え方にし、残りをそれで割って届く日を出す。

半年より前の点が無ければいちばん古い点から。**60日に満たなければペースを出さない**
(短い期間のぶれで、極端な日付が出るのを避ける)。

### 「積立」ではなく「増え方」
系列の値の増え方なので、投資信託なら値上がり・値下がりも入る。積立だけを
取り出すには入金の記録が要り、今は無い。画面に「値動きも入った目安」と書いた。

### 毎年の枠(E07-09)は予測しない
「届かせる」ものではないため。

## 検証 (2026-09-26)
**JVMユニットテスト(192件、うち追加7件)**: `GoalForecastTest`
(届く月と月あたりのペース、半年より前の点が無いとき、60日未満、減っているとき、
達成済み、期日に間に合うか・間に合わせる月額、予測しないもの)

テストを書いたとき、期待値の計算で「3/26〜9/25は182日」と数え違えて1件落ちた
(実際は183日)。コードではなくテストのデータを直した。

**エミュレータで実データ**: 確認用の目標を2つ(`投資信託` と `預金・現金`、
後者は期日つき)ローカルDBに一時的に入れ(Driveには書かない)、詳細画面の
予測を、DBの点から別に計算した結果と比べた(金額は出していない)。

| 系列 | 画面 | 別に計算 |
|------|------|---------|
| 投資信託(増えている) | ◯年◯月ごろ達成 | 一致 |
| 預金・現金(この半年は減っている) | 届かない + 期日に間に合わせる月額 | 一致 |

## 未検証・未実装のまま残したこと
- AI用の書き出し(E03-07)には予測を入れていない
- 目標額が支出で変わる目標(E07-06)は、今の目標額で予測する(目標額の変化は見込まない)
- 積立だけのペース(入金の記録が要る)
