# E08-02: スマホへのインストール・更新運用フロー
親: [E08: リリース・配布](../epics/E08-release-and-distribution.md)

## 概要
ビルドしたAPKをスマホに転送・インストールする一連の流れを確立する。

## 完了条件
新しいAPKができてから、実機で更新が反映されるまでの手順が
迷わず再現できる。

## 手順
[docs/development.md](../../docs/development.md) の「リリース」に書いた。

- 最初の1回: 鍵を作る → リリース鍵のSHA-1をCloud Consoleに登録 →
  **スマホのデバッグ版を消す**
- 毎回: `appVersion` を上げてCHANGELOGに書く → `assembleRelease` →
  `adb install -r`

## 設計の決定

### USBデバッグで入れるのを基本にする
`adb install -r` なら上書きで、スマホのデータ(キャッシュ・認可)が残る。
USBでつなげないときの代わりとして、DriveにAPKを上げてスマホで開く方法も書いた。

### APKを inbox に置かない
inboxはCSVの置き場で、置いたものは全部読もうとする。APKを置くと
「CSVではない」として失敗扱いになり、ログが残る。別の場所に置く。

### デバッグ版とリリース版は同じスマホに同居させない
デバッグ版だけパッケージ名を変える(`.debug`)と同居できるが、GoogleのAndroid
クライアントはパッケージ名で登録するので、もう1つ登録が要る。スマホに入れるのは
リリース版だけにして、デバッグはエミュレータで行う。最初の1回だけデバッグ版を消す。

## 検証 (2026-09-25)
- エミュレータで、デバッグ版の上にリリース版を入れると
  `INSTALL_FAILED_UPDATE_INCOMPATIBLE` で拒まれることを確かめた
  (手順の「デバッグ版を消す」が要る理由)
- 同じ署名のデバッグ版の上書き(`installDebug`、versionCode 1 → 10000)では
  エミュレータのデータ(148点)が残った
