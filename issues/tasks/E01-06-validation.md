# E01-06: バリデーション処理
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
文字コード(Shift-JIS/UTF-8)判定、区切り文字判定、行数0チェック、
極端な異常値の除外など、取り込み前の基本チェックを実装する。

## 完了条件
壊れたCSVや空ファイルを取り込もうとした際に、正常にエラー扱いされる。

## 実装した内容

文字コード判定と空ファイルチェックはE01-04で先に入れてあるので、
ここでは残りをやった。

### 1. 中身で足切りする(拡張子は見ない)
「ファイル名も気にせず放り込む」のが前提なので、拡張子は当てにしない。
先頭バイトの並びで判断する。

| 条件 | 扱い |
|------|------|
| 空 | `中身が空` |
| 10MB超 | `ファイルが大きすぎる` |
| `PK..` で始まる | `Excel(xlsx)かzipのように見える。CSVで書き出して置き直す` |
| `%PDF` で始まる | `PDFのように見える。CSVで書き出して置き直す` |
| `D0CF11E0` で始まる | `古い形式のExcel(xls)のように見える` |
| 先頭8KBにNULバイト | `テキストファイルではない` |

**「読めなかった」ではなく「xlsxだからCSVで出し直して」と言う**のが狙い。
雑に放り込む運用だと、Excelのまま置いてしまうのは普通に起きる。
E01-08でlogsに書くときも、この理由がそのまま役に立つ。

### 2. 区切り文字の判定
カンマ・タブ・セミコロンをそれぞれ試し、**列数が揃っているもの**を選ぶ。
区切り文字を間違えると列が1つにしかならないので、そこで差がつく。

単純に出現回数を数えるやり方だと、摘要欄にカンマが入るタブ区切りの
ファイルでカンマを選んでしまう。「揃っているか」で見ればタブが勝つ
(テストで確認済み)。

どれも2列以上にならなければカンマにしておき、後段の
`rejectRowsReason` が `列が1つしか無い(区切り文字を判定できなかった)`
として弾く。

### 3. 異常値の除外
桁が飛んだ値は、たいてい行がずれて別の列を読んでいるか、区切り文字を
誤判定して数字が繋がっている。**通すより弾くほうが安全**なので、
パースの時点でnullにして行ごとスキップさせる。

| 対象 | 範囲 |
|------|------|
| 金額 | 絶対値10兆円まで |
| 年 | 1900〜2100 |

日付を組み立てる場所が2か所(`parseDate` と `AnserAdapter.readDate`)に
分かれていて、年のチェックが片方しか効いていなかった。
`FieldParsers.dateOf()` に集約して両方が通るようにした。

## 検証結果 (2026-09-25)
ユニットテスト全42件PASS(うちこのタスク分17件)。

実データ3ファイルは区切り文字がカンマと判定され、E01-05までと
同じ結果になることを実機で再確認済み(回帰なし)。

壊れたファイルを実際にinboxに置いての確認は未実施。
xlsx/PDF/バイナリの判定はバイト列を組み立てたテストで確認している。

## 積み残し
- ヘッダー行が無いCSV(1行目からデータ)は検出していない。
  1行目が列名として扱われて1行ぶん失われる(E01-05の積み残しと同じ)。
- 異常値の「除外」はしているが、**除外したことを人間に伝える経路が
  まだ無い**。今はログだけ。E01-08(logsへの書き出し)と
  E03-05(同期結果サマリー)で出す。
