# E01-10: 手動補正データの書き戻し(corrections)
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
「Driveに置かれたデータが正」という原則を崩さないよう、アプリ内で行った
手動補正(自動パース失敗分の修正、現金など元々CSVに載らない数値の追加)は、
ローカルキャッシュだけを直接書き換えるのではなく、補正内容自体を
corrections フォルダにCSV/JSONとして保存する。

補正データはbackup/processedのCSVとは別レイヤーとして扱い、ローカル
キャッシュを再構築する際は「元データ + corrections」を両方読み込んで
最終結果を組み立てる。

## 完了条件
アプリ内で数値を手動修正すると、その内容がcorrectionsフォルダに
記録される。アプリを再インストールしてDriveから再構築しても、
補正内容が失われずに反映される。

## 設計の決定

### 元データは絶対に書き換えない
processedのCSVもbackupのJSONも触らない。補正は**別レイヤー**として重ねる。

- 元データは銀行が出したそのまま残る(後から検証できる)
- 補正を取り消したければcorrectionsから消すだけ
- **パーサーを直して再取り込みしても、補正は生き残る**

3つめが効く。E01-04のパーサーは今後も直す。元データを書き換えていたら、
再取り込みのたびに補正が飛ぶか、逆に補正が古い誤りを上書きし続ける。

### 種類は2つだけ
| 種類 | 用途 |
|------|------|
| `OVERRIDE` | パースを間違えた値を正しい値に直す |
| `MANUAL` | そもそもCSVに載らない値を足す(現金、タンス預金など) |

どちらも「ある日付の、ある項目の、正しい値はこれ」という同じ形なので
実体は同じ。区別は由来を残すためだけのもの。

### キーはMetricと同じ「項目 + 日付」
E01-11の重複判定と同じ形にしてある。同じ日・同じ項目の補正は1つだけ有効。
同じキーの補正が複数あれば`correctedAt`が新しいほうを採る。

### 丸ごと置き換えて書く
差分ではなく`corrections.json`を毎回書き直す。手で直す件数がそもそも
多くなるデータではないし、追記方式は途中で失敗すると壊れる。

### 読めなくても落とさない
correctionsが壊れていても、補正が効かないだけで元データは無事。
壊れた項目は落として読める分だけ返す。

## ファイルの形
`/資産アプリ/corrections/corrections.json`

```json
{
  "formatVersion": 1,
  "corrections": [
    {
      "metricKey": "投資信託",
      "date": "2026-09-01",
      "valueYen": 1500000,
      "kind": "OVERRIDE",
      "note": "パースが間違っていた",
      "correctedAt": 1790000000000
    },
    {
      "metricKey": "現金",
      "date": "2026-09-01",
      "valueYen": 50000,
      "kind": "MANUAL",
      "correctedAt": 1790000000000
    }
  ]
}
```

## 実装
`drive/Corrections.kt`

| 関数 | 役割 |
|------|------|
| `load(api, folders)` | Driveから読む。無ければ空 |
| `save(api, folders, entries)` | 丸ごと書き戻す |
| `apply(points, corrections)` | 元データに補正を重ねる |
| `render` / `parse` | JSONの組み立てと読み取り(テスト用に分離) |

`apply`が「元データ + corrections で最終結果を組み立てる」の実体。
