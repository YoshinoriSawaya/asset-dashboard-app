# E01-13: 認証切れ・オフライン時の挙動
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
OAuthトークンの期限切れ時に、アプリがクラッシュせず再認証を促す
フローを実装する。あわせて、ネットワークがない状態でアプリを開いた
場合もDrive同期をスキップし、ローカルキャッシュの表示のみで
正常に動作させる。

## 完了条件
- トークン期限切れ時、エラーで落ちずに再ログイン画面へ誘導される
- オフライン時、アプリはローカルキャッシュの内容をそのまま表示し、
  クラッシュや長時間のフリーズが発生しない

## 設計の決定

### 認可・リトライ・失敗の仕分けを1か所にまとめた
`drive/DriveSession.kt` が「トークンを取る → Drive操作 → 失敗を仕分ける」
を引き受ける。UI側が毎回この手順を書かずに済む。

結果は4つ:

| 結果 | 意味 | UIの反応 |
|------|------|----------|
| `Success` | 成功 | 結果を出す |
| `ConsentRequired` | 同意が要る | 同意画面を起動 |
| `Offline` | 通信できない | 同期をスキップしてキャッシュを見せる |
| `Failed` | それ以外 | 理由を出す |

### トークン切れは1回だけ黙って取り直す
アクセストークンの寿命は1時間程度なので、アプリを開きっぱなしに
していると普通に切れる。**ユーザーに見せる前に1回リトライする。**
それでも駄目なときだけ同意画面に誘導する。

`DriveException.isUnauthorized`(HTTP 401)で判定する。
この区別はE01-02の時点で仕込んでおいたもの。

### オフラインは「失敗」と別に扱う
圏外は直しようがないので、エラーとして騒がず「同期をスキップした」
として扱う。`DriveException.isOffline` が
`UnknownHostException` / `ConnectException` / `SocketTimeoutException` /
`NoRouteToHostException` を見て判定する。

### 実機で見つかった問題: 圏外だと「同意が必要」になる
機内モードで同期すると、`AuthorizationClient.authorize()` が
**`ConsentRequired` を返す**。そのまま進むと、開けもしない同意画面に
誘導してしまい行き止まりになる(実際にそうなった)。

**認可より先にネットワークを見る**ようにして解決した。
`ConnectivityManager` で `NET_CAPABILITY_INTERNET` を確認し、
無ければ認可を試みずに `Offline` を返す。

ただしこれは「繋がっている」までは保証しない(Wi-Fiに繋がっていても
その先が死んでいることはある)。そちらは実際のリクエストが
`isOffline` で拾う。**二段構え**にしてある。

### タイムアウトを短くした
OkHttpの既定だと圏外で固まる時間が長い。
connect 10秒 / read 30秒 / write 30秒にした
(完了条件の「長時間のフリーズが発生しない」)。

## 検証結果 (2026-09-25)
エミュレータで機内モードにして確認。

| 状況 | 結果 |
|------|------|
| 機内モードで同期 | `オフライン: 同期をスキップしました (ネットワークに繋がっていない)` を約8秒以内に表示。クラッシュもANRも無し |
| ネットワーク復帰後 | `接続OK: <メール> / フォルダは作成済み / 新しいファイルは無し` |

**トークン失効時の挙動は未検証。** 1時間待つか、トークンを人為的に
失効させる手段が要る。コード上は401→再認可→リトライの経路が入っている。
