# E08-03: バージョン管理・変更履歴の記録方法
親: [E08: リリース・配布](../epics/E08-release-and-distribution.md)

## 概要
アプリのバージョン番号の付け方、変更履歴(CHANGELOG)の記録方法を
決める。

## 完了条件
バージョンアップのたびに、何が変わったかが追える状態になっている。

## 決めたこと

### 番号は `MAJOR.MINOR.PATCH`、書き換えるのは1か所
`app/build.gradle.kts` の `appVersion = "1.0.0"` だけを書き換える。
`versionCode`(Androidが更新の可否に使う整数)はそこから計算する
(`1.2.3` → `10203`)。上げ忘れて「更新なのに入らない」が起きない。
minor・patchは99まで(それを超えると計算がずれるのでビルドを止める)。

| 上げるもの | いつ |
|-----------|------|
| MAJOR | v1 → v2 のような区切り(エピックのフェーズ) |
| MINOR | 機能が増えた(タスクが1つ以上終わった) |
| PATCH | 直しただけ |

最初の版は **1.0.0**(v1が揃った版)。

### 変更履歴は `CHANGELOG.md`
リポジトリ直下。版ごとに、利用者から見て何が変わったかを短く書き、
詳しい経緯はタスクへのリンク(E番号)で辿る。コミットの履歴やタスクと
同じことを繰り返さない(CLAUDE.mdの「同じことを2か所に書かない」)。

## 検証 (2026-09-25)
- `appVersion = "1.0.0"` で、APKの中身が `versionName=1.0.0` /
  `versionCode=10000` になることを `aapt2 dump badging` で確かめた
- 以前の `versionCode = 1` から上がるので、エミュレータのデバッグ版は
  上書きで入った
