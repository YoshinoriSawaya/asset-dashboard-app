# 資産ダッシュボード

個人用の資産形成ダッシュボードAndroidアプリ。銀行から落としたCSVを
Google Driveの `inbox` に放り込むだけで取り込み、資産の推移を1か所で見る。
ホームウィジェットは「何か対応が必要か」だけを色で知らせる。

ストア非公開・自分専用。マネーフォワード等への課金を避けるために自作している。

## いまどこまで動くか

**v2。2026-09-26からスマホに入れて使っている。** 今の版と版ごとの変化は [CHANGELOG.md](CHANGELOG.md)。
進捗と設計の経緯は [issues/README.md](issues/README.md)。

### 取り込み
アプリを開いて「Driveと同期」を押すと:

1. Googleアカウントで認可(初回だけ同意画面)
2. `/資産アプリ/` 配下の6フォルダを用意(無ければ作る)
3. `inbox` のCSVを読んでパース(銀行の明細、資産推移、カードの利用明細、証券口座の保有商品一覧)
4. 正規化した結果を `backup` にJSONで保存
5. 元ファイルを `processed` へ移動
6. 問題があれば `logs` に理由を残す
7. `backup`・`corrections`・`settings` からローカルDBを作り直す

ボタンを押さなくても、開いたときに手元のデータが30日より古ければ自動で同じことをする。
トップには前回の同期の要約が出て、タップで詳細(読めなかった行など)を見られる。

### トップ
- 純資産(「純資産に数える」を選んだ系列の合計。「合計」とその内訳のように重なる系列があるので全部は足さない)、
  リマインダー(全N件)の1行、目標と系列が最新値と今月の増減付きで並ぶ。系列は色分けされ、一覧・推移の線・円グラフで同じ色
- 一覧の下に、ほかの画面への入口が「振り返る・貯める/備える・追加する・設定/取り込み」のまとまりごとに2列のボタンで並ぶ
- 月次・年次サマリー(系列ごとの増減と入出金)
- 系列の詳細: 推移の折れ線・増減の棒・月ごとの表。値の補正・手入力(Driveの `corrections` に保存)。
  表示名の変更・一覧から隠す・まとめ先(NISAの区分を投資信託の内訳に、など)(Driveの `settings` に保存)。
  銀行明細の残高から口座ごとの残高の系列もできる

### 振り返る
- **前の月の振り返り**: お金の流れ・いつもより多かったカテゴリ・予算の結果・固定費の変化・純資産の増減を1画面で
- **カテゴリ別の支出**: 月ごとにカテゴリ別の額・割合・直近の平均との差(いつもよりはっきり多いものに印)。押すとその月の明細。
  上に直近12か月の積み上げ棒(押すとその月へ)。カテゴリごとに月の予算を決めると「予算の◯%」が出る
- **固定費・サブスク**: 毎月出ていく支払いを明細から見つけ、月の平均・年額の見込み・定額か変動か・先月止まったか。
  定額の支払いの値上がりに印(年に1回の支払いは入らない)
- 明細のカテゴリ: 摘要の言葉でカテゴリ(生活費・遊び代・大型出費・振替・積立投資)を付ける。CSVでまとめて取り込める。
  直近1年半に使った摘要だけを出し、カテゴリの無い出金だけに絞れる

### 貯める・備える
- **純資産の見通し**(純資産の画面): 5・10・20・30年後の目安と線グラフ。投資の系列は想定利回りで増やし、
  それ以外は毎月の残り(収入 − 消費)を足していく。大型出費の予定はその月に引く
- **積立投資の目安**: 収入から消費と守りのお金を引いた残りの8割を、今の積立額と比べる
- **余剰資金の配分**: ボーナスなどの額を入れると、下限の回復 → 積み増し中の今月分 → 各目標の不足分の順に、どこへいくら回すかの案
- **投資信託の損益**: 保有商品一覧から、ファンドごとの評価額・取得額・含み益・平均取得単価と現在値。取り込むたびの推移。
  ファンドごとに基準価額の取り先(ISIN・協会コード)を決めると、毎朝の基準価額と平均取得単価の比べも出る。
  取り先はファンド名で投資信託協会のサイトを探して決められる(書き方まで同じものが1本ならまとめて保存)。
  取り先のあるファンドは、行を開くと基準価額の推移(3か月・1年・全期間、平均取得単価の破線つき)も見られる
- 系列の詳細で想定利回りを決めると、このまま積み立てたときの10・20・30年後の評価額の目安(積立額にする積立投資のカテゴリも選べる)
- **大型出費の予定**: 向こう3年の見込み額つきのリマインダーと期日のある目標。家電や車のように何年かごとの出費は、リマインダーに
  「何年ごと」と積立先を入れると、積立の目標に向こう1年に要る額とならした月々の積立額が出る(物価上昇率も掛けられる)。
  1行1項目のCSV(`settings/plan.csv`)でまとめて取り込める

### 目標とリマインダー
- 目標(Goal)の進捗が一覧と詳細に出る。目標額は決まった額のほか、「生活費の何か月分」で自動にもできる
- 毎年1月にリセットする枠(ふるさと納税など)、期日の何か月前から積み増すか、足りないとき何か月で埋めるか を決められる
- 生活防衛資金には下限を決められ、期日の目標が足りないときに下限までなら取り崩して補えるかが出る
- 同じ系列を複数の目標で測るときは、一覧の上の目標から順に残高を割り当て、目標ごとに色分けした積み上げグラフで見られる
- 目標の詳細には、今のペースならいつ届くか、生活防衛資金には生活費の何か月分あるか・いつ目標を割るかの目安
- リマインダーは期日順の一覧で見て、済みにすると次の期日へ進む

### 通知
端末が1日1回(朝)自分で確かめて出す。サーバーやFCMは使わない。金額は出さない。
- 同期の催促、リマインダー、目標の不足、年末の枠、積み増しの時期、生活防衛資金の下限
- 前の月の結果: いつもより多かった消費のカテゴリ、予算を超えたカテゴリ、固定費の値上がり(押すと前の月の振り返り)
- 投資信託: 取り先を決めたファンドの基準価額を投資信託協会の公開データから取り、平均取得単価より10%以上上がったら
  (押すと投資信託の損益。朝の確認で通信するのはこれだけ)

### 守り・そのほか
- ホーム画面のウィジェットは、同期が必要になると赤くなる(金額は出さない)
- アプリは開くときに生体認証か端末の画面ロックで守る。人前では金額を「%」や「マスク」に切り替えられる
- 資産の状況をAI相談用のMarkdownにしてコピーできる(カテゴリ別の支出と毎月の支払いも入る。振込の相手は伏せる)
- 入れ直しても同期すれば元に戻る

## Driveのフォルダ構成

```
マイドライブ/資産アプリ/
  inbox/        ← CSVをここに放り込む(人間が触るのはここだけ)
  processed/    ← 取り込み済みCSVの移動先
  backup/       ← 正規化済みデータ(JSON)
  corrections/  ← 手動補正
  settings/     ← 人が決めたもの(下)
  logs/         ← 取り込み失敗の記録
```

| `settings/` のファイル | 中身 |
|---|---|
| `items.json` | 項目(目標・リマインダー・系列の表示名など)の定義 |
| `categories.json` | 明細のカテゴリ、摘要の言葉の決まり、カテゴリごとの月の予算 |
| `funds.json` | ファンドごとの基準価額の取り先(ISIN・協会コード) |
| `plan.csv` | 大型出費の予定のまとめ取り込み(置いたときだけ) |
| `category_rules.csv` | カテゴリの決まりのまとめ取り込み(置いたときだけ) |

## ビルドと実行

このマシンでは `java` も `adb` もPATHに入っていないため、
`./gradlew` をそのまま叩いても動かない。

**手順は [docs/development.md](docs/development.md) にまとめてある。**
ビルド、エミュレータの起動、画面の確認、ログの見方、DBの覗き方まで。

## 構成

| 場所 | 中身 |
|------|------|
| `app/src/main/java/.../drive/` | Drive API、認可、同期の流れ |
| `app/src/main/java/.../csv/` | CSVのパース、バリデーション、重複検出 |
| `app/src/main/java/.../data/` | Room(ローカルキャッシュ)と、表示用の計算(集計・目標・予測・純資産) |
| `app/src/main/java/.../ui/` | Composeの画面と、グラフ(`ui/chart/`) |
| `app/src/main/java/.../notify/` | 端末の中で出す通知(1日1回の確認) |
| `app/src/main/java/.../widget/` | ホーム画面のウィジェット(Glance) |
| `app/src/main/java/.../lock/` | アプリのロック(生体認証・画面ロック) |
| `issues/` | エピックとタスク。設計の経緯もここ |
| `docs/` | 全体の仕組みと開発手順 |

設計の考え方は [docs/architecture.md](docs/architecture.md)。

## 個人情報の扱い

このリポジトリに**実データのCSVは置かない**。口座番号・氏名・残高が入る。
テストは実ファイルで起きた事象を最小の形に写したものを使っている。

`.gitignore` で keystore・`google-services.json`・`local.properties` も
除外してある。
