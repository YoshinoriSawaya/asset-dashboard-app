# E10-04: 積立投資の目安(NISA積立額の総合調整提案)
親: [E10: 純資産・資金配分の統合](../epics/E10-net-worth-allocation.md)

## 概要
今のNISAの積立額が多すぎないか・増やせるかを、生活防衛資金・積み増し中の目標・大型出費の積立などを
踏まえて判断し、具体的な金額で出す。E07-08(生活防衛資金要因の減額提案)は、この機能の一部として統合される。

当初は「NISAの月次の積立額を本人が入れる」のを待っていたが、本人の案(2026-09-26)で、
**収入の平均と支出の平均から積立投資に回せる額を出す**形にした。今の積立額はクレカ積立の明細から分かるので、
入力を待たずに作れた。

## 完了条件
「今の積立額 → 月◯円(増やせる/減らしたほうがよい)」が、その根拠とともに出る。
あくまで目安で、実行は本人が証券口座で行う。

## 作ったもの
- `data/InvestPlan.kt`:
  ```
  目安 = (収入 − 消費(生活費+遊び代) − 生活防衛資金の月額 − 大型出費の積立の月額 − 積み増し中の目標の月額) × 8割
  ```
  今の積立額は、カテゴリの種類が「積立投資」の明細の月平均(E07-21)
- `ui/InvestPlanScreen.kt`: トップの「積立投資の目安」から開く。目安・今の積立との差・計算の内訳を並べる。
  残りが無いとき・今の積立額が分からないときは、そう出す

## 設計の決定(本人が決めたもの)
- **収入の平均 − 支出の平均**で出す(本人の案)
- **ボーナスも通常の収入として平均に入れる**
- **ゆとりは2割**(残りの8割を目安にする)
- 振替・遊び代・家具などは、明細のカテゴリ(E07-21)で分ける

## 設計の決定(こちらで決めたもの)
- **守りのお金を先に引く**: 生活防衛資金の足りない分(E07-19の月額)・大型出費の積立(E07-15)・積み増し中の目標(E07-11。
  元のE10-04の「頭金の準備を優先する」)。余剰資金の配分案(E10-02)と同じ優先順位
- **大型出費(家具・家電)は消費に入れない**: 積立の月額で引くので、二重に引かない
- **平均の月の選び方は生活防衛資金(E07-06)とそろえた**: 直近6か月、今月と明細の無い月は使わない
- **1000円単位で切り捨て**: 目安を多めに出さない

## 検証 (2026-09-26)
**JVMユニットテスト**: `CategoriesTest`(種類ごとの収入・消費・積立投資、目安の計算と守りのお金、今月しか無いとき)

**エミュレータで、本人のデータで確認した**(額はマスク):
- 目安の画面に計算の内訳が並んだ
- 今は「収入から引くと残りがありません」「今の積立額はまだ分かりません」と出る。引き継いだ「生活費以外」に
  振替・クレカ積立が混ざっていて消費に入り、「積立投資」のカテゴリがまだ無いため(E07-21の未検証を参照)。
  はじめ「今のままでよい」と出ていたのを、この2つを分けて出すように直した

### カテゴリを付け直したあと (2026-09-27)
本人が振替・積立投資のカテゴリを付け直し(E07-22のまとめ取り込みも済み)、エミュレータでDriveと同期した
本人のデータで確かめた。画面の文字を `uiautomator` で取り出し、DBから別に計算した値とスクリプトの中で
比べた(額は会話にも出していない)。

| 項目 | 別に計算したもの | 結果 |
|------|-----------------|------|
| 平均に使った月数 | 明細のある月のうち今月より前の直近6か月 | 一致 |
| 収入・消費・今の積立 | 明細から、`Summary.cashflow` と同じ決まり(振替・カードの行・カード引き落としの扱い)で | 一致 |
| 生活防衛資金の月額 | 目標の詳細の「◯か月で埋めるなら 月々」 | 一致 |
| 大型出費の積立の月額 | 積立の目標の詳細の「ならすと 月々」の合計 | 一致 |
| 残り・8割 | 画面の値から計算し直す | 一致 |

**出た目安**: 残りがマイナスで目安は0、「今の積立は減らしたほうがよい」。付け直す前の「今の積立額は
まだ分かりません」は出なくなった(積立投資の明細が拾えている)。残りがマイナスになるのは主に次の2つ:
- 生活防衛資金が目標に届いておらず、足りない分を6か月で埋める月額が収入の半分近くになる
  (守りのお金を先に引く、というこのタスクの決定どおりの結果)
- 消費の半分以上が**カテゴリの無い明細**。カテゴリが無い明細は消費に数えるので、振替や大型出費が
  混ざっていれば消費が多めに出る

どちらも計算の誤りではなく、設定とカテゴリの付け方で変わる。

## 未検証のまま残したこと
- カテゴリの無い明細のうち、本当は振替・大型出費のものがどれだけあるかは見ていない(本人が見直す)
- 通知はしない(画面を開いて見る)
- 一括投資(ボーナスでまとめて入れる)の提案はしない。まとまったお金は余剰資金の配分案(E10-02)で扱う
