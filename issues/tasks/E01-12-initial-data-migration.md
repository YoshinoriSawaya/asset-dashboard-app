# E01-12: 既存データ(マネーフォワード等)の初回移行
親: [E01: Google Drive連携基盤](../epics/E01-drive-integration.md)

## 概要
これまでマネーフォワード等に貯まっている履歴データを、一度だけこの
仕組みに取り込むための移行作業。各銀行のネットバンキングからCSVを
個別にダウンロードし、inboxにまとめて置いて一括処理する。

継続運用(月1でinboxに置く)とは別の「一回限りの初期投入」として扱う。

## 完了条件
過去データがローカルキャッシュ・backupに反映され、アプリのサマリー
画面に過去分の推移が表示される状態。

## 現状: 着手できない

このタスクは**作業(オペレーション)であって実装ではない**。
そして完了条件が2つの未実装機能に依存している。

| 依存 | 状態 |
|------|------|
| ローカルキャッシュへの反映 | E02(スキーマ未設計)待ち |
| サマリー画面での表示 | E03待ち |

いま銀行から過去ぶんのCSVを落としてinboxに入れても、
パースされてbackupに書かれるだけで、**確認する画面が無い**。
移行がうまくいったかを判断できないまま大量のファイルを流すことになる。

## 前提は揃っている
移行そのものに必要な仕組みはE01で出来ている。

- E01-04 … 3形式のアダプター(銀行が増えても列の顔ぶれで拾える)
- E01-05 … 未知の形式でも金額だけは拾うフォールバック
- E01-06 … xlsx/PDFを置いてしまっても理由付きで弾く
- E01-11 … 期間が重なるCSVを続けて入れても二重計上しない

特にE01-11は移行で効く。銀行ごとにダウンロードできる期間がまちまちで、
重なるのが普通なので。

## 実施するときの段取り(メモ)
1. E02・E03が終わっていること
2. **まず1行だけのCSVを1つ置いて試す**。大量投入の前に、
   その銀行の形式が既知アダプターに当たるかを確認する
3. 当たらなければ`未知のフォーマット`か`(推測)`と表示されるので、
   必要ならアダプターを足す(E01-04に1つ追加するだけ)
4. 問題なければ銀行ごとに全期間ぶんを投入する
5. サマリー画面で推移が連続しているか、抜けがないかを見る

一度に全部入れない。銀行1つずつ入れて確認するほうが、
問題が起きたときに原因が分かる。

## ステータス
未着手(前提のE02・E03は完了。本人が過去ぶんのCSVを落としてinboxに置くのを待っている)
