# E02-05: 月次・年次集計ロジック
親: [E02: ローカルデータモデル・キャッシュ基盤](../epics/E02-local-cache-and-model.md)

## 概要
ローカルDBのMetricデータから、月次・年次の増減・合計を計算する
ロジックを実装する。

## 完了条件
任意の月・年を指定すると、その期間の資産推移(増減額)が計算できる。

## 作ったもの
`Summary`(純粋関数だけ)。入力はDAOの結果(`MetricPointDao.series` /
`BankTransactionDao.between`)。

| 関数 | 返すもの |
|------|---------|
| `metricChange(key, points, 期間)` | `MetricChange`: 期首・期末の値と増減 |
| `cashflow(transactions, 期間)` | `Cashflow`: 収入・支出・差し引き・件数 |
| `monthlyMetric` / `yearlyMetric` | データのある最初の月(年)から最後まで、抜けた月も含めた一覧 |
| `monthlyCashflow` / `yearlyCashflow` | 同上 |
| `month(YearMonth)` / `year(Year)` | 期間(両端を含む) |

## 設計の決定

### Metricは足さずに差を取る、明細は足す
| | 性格 | 期間の値 |
|---|---|---|
| Metric | 時点の残高 | **増減** = 期末の値 − 期首の値 |
| 明細 | 動いた額 | **合計**(収入・支出それぞれ) |

Metricを期間内で合計すると、残高を何度も数えることになり意味を持たない。

### 期首の値は「期間が始まる前の最後の値」
「前月末の値」と決めると、前月にデータが無い月は計算できない。
直前の観測値を使えば、データの抜けた月があってもその次の月の増減が出る。

- 期間中にデータが無い月は、期末を**不明(null)**として0と区別する。
  増減も出さない
- 最初の月は比べる相手が無いので増減を出さない(期末の値は出す)

### 概要は「Metricデータから」だが、明細の集計も入れた
後に続くタスクが月次の**支出**を必要としている
(E07-06 生活防衛資金の目標額、E09-02 枯渇予測)。支出は明細からしか
取れないので、ここで一緒に用意した。

### 「合計」列を他の列と足さない
資産推移CSVの `合計` はそれ自体がMetricの1系列で、ここでも他の系列と
同じに扱う(系列ごとに集計するだけで、系列をまたいで足さない)。
系列をまたいだ合算はE10-01の仕事で、そこで二重計上に注意する(E02-01)。

### DBを読む部分は作っていない
集計はDAOの結果を渡せば計算できる。画面(E03-03)がどの単位で読むか
決まっていないので、読み出しのラッパーはそのときに作る。

## 検証 (2026-09-25)

**JVMユニットテスト(107件、うち追加10件)**: `SummaryTest`
- 月の増減、データの抜けた月・その次の月、最初の月
- 年をまたいだ年次の増減
- 入出金の合計が期間の両端を含むこと、月次・年次の一覧

**実データ**: エミュレータの実DBに対して、`Summary`の結果と、
**同じ値をSQLで別に計算したもの**を突き合わせる一時的なテストを走らせた
(金額は出力しない。確認後に削除)。

| | 突き合わせた範囲 | 結果 |
|---|---|---|
| Metric | 4系列 × 13か月(2025-09〜2026-09)= 52件の期首・期末 | 全一致 |
| 明細 | 2か月(2026-08、09)の収入・支出・件数 | 全一致 |
| 年次 | 年次の支出の合計 = 月次の支出の合計、件数の合計 = 全件数 | 一致 |

一時テストの最初の版は `initializationError` で落ちた。`= runBlocking { ... }` の
最後の式が `Log.i`(Intを返す)だったため、テスト関数の戻り値がIntになって
JUnitに弾かれた。`runBlocking<Unit>` で直した。

## 気をつけること(後続タスク向け)
- **支出には自分の口座間の振替やカードの引き落としも入る。** 明細の
  出金をそのまま足しているため。E07-06やE09-02で「生活費」として使うなら、
  振替を除く仕組みが要る。カードの二重計上はE01-14で扱う
- 同じ日・同じ額・同じ摘要の取引は1件に潰れる(E01-11の既知の限界)ので、
  支出が実際より少なく出ることがある

## 未検証のまま残したこと
- 集計結果を**画面で**見てはいない(画面はE03-03)
- 実データの明細は2か月分しか無いので、年をまたいだ明細の集計は
  ユニットテストでしか確かめていない
