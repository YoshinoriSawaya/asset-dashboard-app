# E06-02: Driveからのローカルキャッシュ再構築フロー
親: [E06: セキュリティ・バックアップ復元](../epics/E06-security-and-restore.md)

## 概要
アプリを削除・再インストールした際、Driveのbackup/corrections/settingsから
ローカルDBを再構築する初期化フローを実装する(settingsはE02-01で追加)。

## 完了条件
再インストール後、Driveと同期するだけで元の状態(数値・補正内容含む)
が復元される。

## 作ったもの(新しい処理は要らなかった)
E02-03で「**同期のたびにDriveの中身(backup・corrections・settings)からキャッシュを
丸ごと作り直す**」形にしてあるので、入れ直した直後の同期がそのまま復元になる。
さらにE02-04で「手元にデータが無ければ開いたときに自動で同期する」ので、
入れ直して開き、Googleアカウントを選ぶだけで元に戻る。専用の復元画面は作っていない。

## 検証 (2026-09-26)
エミュレータで、実際にアプリを消して入れ直した。

1. 補正(手入力の点)と、見込み額つきのリマインダーを確認用に足す
   (corrections・settingsの両方に中身がある状態にする)
2. 同期 → `149点 / 明細19件 / 項目6件`、指紋 `78f0469d`(E06-03)
3. `adb uninstall`(ローカルのDB・設定・Googleの認可がすべて消える)→ 入れ直す
4. 開く → データが無いので自動で同期 → アカウントの選択 → 同期
5. `149点 / 明細19件 / 項目6件`、**指紋 `78f0469d`(消す前と一致)**

確認用の補正とリマインダーは後で消した(148点・4項目に戻した)。

## 端末にだけあって、戻らないもの
消えても困らないものだけ(どれも作り直せるか、失っても1回余計に何かが起きるだけ):
- 取り込み済みファイルの記録(`ingested_file`。inboxのファイルを読み直すだけ)
- 前回の同期の要約(E03-05)、自動同期の間引き(E02-04)、通知を最後に出した日(E05)
- 通知の許可(入れ直すと、もう一度トップのバナーで許可する)
