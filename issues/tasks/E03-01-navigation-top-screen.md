# E03-01: ナビゲーション構造・トップ画面
親: [E03: ダッシュボードUI・詳細画面](../epics/E03-dashboard-ui.md)

## 概要
アプリ全体の画面遷移構造を作る。トップ画面には登録済みの
Metric/Goal/Reminder項目を一覧表示する。

## 完了条件
トップ画面から各項目をタップして詳細画面に遷移できる。

## 作ったもの

| ファイル | 役割 |
|---------|------|
| `ui/AppRoot.kt` | 画面遷移(ルート文字列のスタック)と、同意画面の起動 |
| `ui/TopScreen.kt` | 同期の状態 + 項目の一覧 |
| `ui/ItemDetailScreen.kt` | 遷移先。中身はE03-02 |
| `ui/DashboardViewModel.kt` | キャッシュの読み出しと同期 |
| `ui/Formatters.kt` | 金額・割合・日数の書式 |
| `data/ItemOverview.kt` | 一覧の1行ぶんの値(純粋関数で組み立てる) |
| `drive/FullSync.kt` | 同期の中身。`MainActivity` にあったものを移した |

一覧の各行の右側に出すもの:

| 種類 | 主な値 | 補足 |
|------|-------|------|
| Metric | 最新値 | 今月の増減(E02-05)。今月のデータが無ければ最新の日付 |
| Goal | 進捗% | 目標額。系列を紐づけていなければ「進捗不明」 |
| Reminder | あと何日 | 期日 |

## 設計の決定

### 画面遷移はライブラリを使わない
画面はトップ・詳細・サマリー・補正の数枚で、深い階層もディープリンクも無い。
`"top"` `"item/<id>"` という文字列を積むスタックと、戻るボタンの
`BackHandler` だけで足りる(CLAUDE.mdの「過度な抽象化を避ける」)。
文字列なので `rememberSaveable` で回転しても残る。

画面が増えて遷移が複雑になったら、そのときNavigationを入れる。

### 同期はViewModelに移した
E02-04では画面(`LaunchedEffect`)で開いたときの判定をしていたので、
**回転などでActivityが作り直されるたびに判定が走る**のを未検証として残していた。
ViewModelの初期化は開いたときに1回だけなので、これで解消する。

同意画面はActivityからしか出せないため、ViewModelは「出してほしい」という
状態(`consentRequest`)を出し、画面がそれを見て起動する。

### 一覧の値は表示のたびに計算する
項目に現在値を持たせない方針(E02-01)のとおり、`ItemOverview.load` が
項目と系列の点から毎回組み立てる。今月の増減はE02-05の `Summary` を使う。

### 一覧には隠した項目を出さない
`hidden` の項目は飛ばす。隠す操作の画面はまだ無い(settingsを書く画面と
一緒に作る。E07-01)。

## 検証 (2026-09-25)

**JVMユニットテスト(115件、うち追加8件)**: `ItemOverviewTest`
- Metricの最新値と今月の増減、今月のデータが無い場合、データの無い系列
- Goalの進捗、系列を紐づけていないGoal
- Reminderの残り日数(過ぎたら負)
- 金額・割合・日数の書式、ルートからidを取り出す

**エミュレータで実データ**:
- トップに4系列(合計・年金・投資信託・預金・現金)が、最新値と
  今月の増減付きで並ぶことをスクリーンショットで確認
  (実額が写るので画像は確認後に削除した)
- 項目をタップすると詳細画面に移り、戻るボタンでトップに戻る
- **回転してもやり直さない**: 期限切れの状態で開いて自動同期を1回走らせ、
  その後に画面を2往復回転させた。同期は増えなかった(logcatで確認)
