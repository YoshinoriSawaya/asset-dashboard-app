# E06-01: アプリロック(生体認証/PIN)
親: [E06: セキュリティ・バックアップ復元](../epics/E06-security-and-restore.md)

## 概要
アプリ起動時に生体認証またはPINでロックする。ウィジェットは通知の
みなのでロック対象外。

## 完了条件
アプリを開くと認証を求められ、成功しないと中身が見えない。

## 作ったもの
| いつ | どうなる |
|------|---------|
| アプリを開いたとき | ロック画面になり、認証を求める |
| 1分以上裏にいて戻ったとき | もう一度ロックする |
| 1分未満で戻った・画面を回した | ロックしない |

- 認証は `BiometricPrompt`(androidx.biometric 1.1.0)で、**生体認証か端末の画面ロック**
  (PIN・パターン・パスワード)
- トップの一番下に「アプリのロック」のスイッチ(既定は入)。端末に画面ロックが無ければ
  「ロックは効きません」と出して、開いたままにする
- 最近使ったアプリの一覧に、画面のサムネイル(金額)を出さない(Android 13以降)
- ウィジェットは対象外(数字を出していない。E04)

## 設計の決定

### アプリ専用のPINは作らない
端末の画面ロックをそのまま使う。専用のPINは覚えるものが増え、忘れたら自分の
データを見られなくなる(Driveから入れ直しても、今度は新しいPINが要る)。
端末の画面ロックなら、忘れても端末の側で戻せる。

### ロックの状態はプロセスの間だけ持つ
画面の回転でActivityが作り直されてもロックし直さないよう、状態をActivityではなく
`AppLock` に持つ。1分の判定は、裏に回った時刻(`onStop`)と戻った時刻(`onStart`)の差。
アプリのプロセスが終われば、次はロックから始まる。

### 画面ロックの無い端末では、ロックできないことを見せる
ロックをかけようとしても認証の手段が無い。黙って開くのではなく、トップに
「この端末には画面ロックが無いため、ロックは効きません」と出す。

### MainActivityをFragmentActivityにした
`BiometricPrompt` がFragmentActivityを要るため。Composeの画面はそのまま動く。

### 画面の撮影は禁止していない(FLAG_SECUREは使っていない)
使うとスクリーンショットも撮れなくなり、確認(adbでの画面の確認)もできない。
最近使ったアプリの一覧のサムネイルだけを消した。

## 検証 (2026-09-26)
**JVMユニットテスト(210件、うち追加4件)**: `AppLockTest`
(最初はロック、1分未満は戻さない、1分以上でロックし直す、裏に回っていなければ変えない)

**エミュレータ**:

| 手順 | 結果 |
|------|------|
| 端末に画面ロックなし | 中身が見え、「ロックは効きません」の注記 |
| PIN(1234)を設定して開く | 端末のPINの画面が出て、入れると中身が見えた |
| 5秒後に戻る / 回転 | ロックされない |
| 65秒後に戻る | ロックされ、PINで解除できた |
| スイッチを切って開き直す | ロックされない |

確認後にスイッチを入に戻し、PINを消した。

## 未検証のまま残したこと
- 生体認証(指紋・顔)での解除。エミュレータではPINで確かめた
- 実機
- 通知をタップして開いたとき(ロック画面から始まるはずだが、見ていない)
